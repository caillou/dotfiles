## What to build

Generate the Karabiner rules from the karabiner.ts source kept inside the dotfiles repo.

- Copy the source from the karabiner.ts repo into `.karabiner/` in the dotfiles repo (dot-prefixed, so chezmoi ignores it without a rule): the single TypeScript rules file, `package.json`, the lockfile, a minimal tsconfig, and a `.gitignore` with `node_modules/`. Drop the starter README; a few lines in the dotfiles README replace it.
- Per the Karabiner research in the notes: keep karabiner.ts (maintained, 1.38.0, covers KE 16); pin it as `^1.38.0` with a committed lockfile; keep `tsx` as the runtime; add a `dev` script `tsx watch src/index.ts` for iterating; keep the `update` script for deliberate bumps.
- The source already targets "Default profile" (retargeted 2026-09-11), which Karabiner creates on first launch, so no profile has to be created by hand.
- `run_after_50-karabiner.sh.tmpl`, every apply: exit with a message unless Karabiner is installed AND `~/.config/karabiner/karabiner.json` exists (Karabiner writes it on first launch; the manual checklist covers launching it). Exit silently if `hash_unchanged karabiner <hash of source + lockfile>` and a successful build is recorded. Else, with `~/.asdf/shims` on PATH from the preamble, `npm ci` and the build, which writes the rules into Karabiner's config file preserving its other settings; store the hash on success. A Karabiner installed or launched after the first sync gets its rules on the next sync.
- The generated `karabiner.json` never enters the repo.
