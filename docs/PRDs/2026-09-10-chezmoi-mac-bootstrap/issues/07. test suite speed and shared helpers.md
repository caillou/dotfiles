## What to build

The deferred cleanup from the final health review: make `bats tests` fast enough to keep in the pre-commit hook, and collapse the harness that parallel authorship wrote thirteen times.

- **Speed.** `bats tests` is 3:08 wall, of which `tests/defaults.bats` is 94 s: each of its 35 tests re-renders and re-runs the whole defaults script, spawning ~120 stub processes. Run the script once in `setup_file` into a log under `$BATS_FILE_TMPDIR` and have the read-only value tests (keyboard, scrolling, trackpad, force click, tap to click, pointer speed, screenshots, Finder, icon view, window manager, Dock, dictation, informational rows, hotkey 164, the two ordering tests) assert against it. Keep a per-test run only where the test changes state first: `POINTER_LIVE`, `PMSET_STATE`, `OSASCRIPT_FAILS`, the wallpaper store, the missing-python case.
- **Shared helpers** in `tests/helpers.bash`:
  - `isolate_home()` for the HOME/`XDG_*_HOME` block copied verbatim into 13 of the 17 bats files (`config`, `packages`, `report`, `asdf`, `shell`, `defaults`, `dock`, `downloads-view`, `display`, `iterm2`, `karabiner`, `hammerspoon`, `git-github-ssh`, the last with `pwd -P`), comment included.
  - `stub <name> [log] [exit]` reading an optional body from stdin and prepending `$BATS_TEST_TMPDIR/bin` to PATH once, replacing the five variants (`facts.bats:15`, `defaults.bats:71`, `downloads-view.bats:31`, `dock.bats:46` and `:55`, `display.bats:42`) and the shebang/log/chmod preamble each tool-specific stub hand-writes.
  - `chezmoi_config` gains an optional source directory, so `hammerspoon.bats:29 sandbox` and `karabiner.bats:188 karabiner_script` stop writing their own TOML. `tests/shellcheck-scripts.sh` is POSIX sh and cannot source `helpers.bash`; leave its copy with a comment saying so, or give it `--override-data-file`.
- **Tests that restate their data** assert behaviour instead: drop the byte-for-byte version pins in `tests/asdf.bats:99` (test 2 at `:105` already checks the shape), the row counts in `tests/packages.bats:231`, and render `tests/report.bats:133-156` with the file's own `FAKE_APPS`/`render_apps` instead of asserting real `apps.yaml` rows. `tests/dock.bats:229` is the seed allow-list's acceptance test; keep it if wanted.
- **Dead branch:** `tests/asdf.bats:299-300, 309` skip on "the shell issue has not landed its startup files yet"; both issues landed, so the guard can never fire. Drop it so a future rename of `config.fish` fails loudly, and drop the `--exclude=README.md` comment with it.
- **`.iterm2/README.md`** restates the main README's iTerm2 section (the four keys, write-back on quit, the exclusion claim) in a second place that will drift. Reduce it to the one fact the main README lacks (what `ayu dark.itermcolors` is) and a pointer.
- **Wording:** the retry sentence has four spellings across scripts 10, 20, 21, 30, 40, 50, 63; settle on "the next apply tries again" everywhere. `run_onchange_after_61-dock.sh.tmpl:22` should print the same `chezmoi state delete-bucket --bucket=entryState && chezmoi apply` hint that 62 prints, since the README names the Dock case as the reason that command exists. Fix the `downloads view:` prefix (`62:24-25`) to `downloads-view:` like every other script.
- **Optional, if it stays simple:** absorb the repeated `FISH` and `BREW` seams, the `$STATE/Brewfile` path and the `shasum -a 256 | cut -d ' ' -f 1` hash shape (10:58, 40:45, 50:35) into `facts.sh` as `FISH`, `BREW`, `BREWFILE` and a `file_hash` helper next to `store_hash`, and write the `DOTFILES_<TOOL>` seam rule as one paragraph in the preamble's header.
- **Display script sudo on a settled Mac.** The display script asks for the admin password on every apply, because it reads root's CoreBrightness domain to decide whether there is anything to import. When the `auto-brightness-applied` marker is already set it should skip that read, so a settled Mac applies without sudo; first-apply behaviour is unchanged.
