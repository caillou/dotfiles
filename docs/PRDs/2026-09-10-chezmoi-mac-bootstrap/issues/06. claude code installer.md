## What to build

Install the `claude` CLI from the bootstrap, on both Macs, when it is missing.

- New script `.chezmoiscripts/run_after_45-claude-code.sh.tmpl`, between asdf (40) and Karabiner (50), inlining the shared preamble like every other `after` script.
- Guard: `has_command claude` or `[ -x "$HOME/.local/bin/claude" ]` means done, print nothing and exit 0. The second half is needed because the native installer links the CLI into `~/.local/bin`, which the preamble does not put on PATH.
- Otherwise download `https://claude.ai/install.sh` to a `mktemp` file with a cleanup trap, require it to be non-empty and to start with `#!`, then run it with `${DOTFILES_BASH:-/bin/bash}` (the seam name the Homebrew installer already uses). `curl` gets a `DOTFILES_CURL` seam of its own: the preamble puts Homebrew's bin first on PATH, so a PATH stub cannot be relied on to win, and the `DOTFILES_<TOOL>` convention covers exactly that case. Never `bash -c "$(curl ...)"`, for the reason in [06. homebrew installer fails loudly on an empty download](<06. homebrew installer fails loudly on an empty download.md>).
- Every failure - curl non-zero, empty file, no shebang, a failing installer, an installer that left no `~/.local/bin/claude` - prints one line in the repo's pattern, `claude-code: <what happened>. The next \`chezmoi apply\` downloads the installer again.`, and exits 0 so the apply continues. This is a `run_after_` script, not `run_once_`, so it retries on the next apply by construction: no marker, no hash.
- The CLI updates itself, so nothing here keeps it current and no version is pinned. This Mac already has it that way at `~/.local/bin/claude` (2.1.270), a symlink into `~/.local/share/claude/versions/`.
- Not the Homebrew cask: it lags behind the CLI's own releases, and casks are never installed on the managed Mac, so the Brewfile route would never reach the machine that needs it.
- Nothing in the script reads `.managed` or `.personal`: the CLI is a command-line tool, not a desktop app, and both Macs get it.
- Register the name in `tests/scripts.bats` (the fixed list and the ordering test) and in the README layout table and the sentence listing what the apply does. `.chezmoiignore` needs nothing: `.chezmoiscripts/` is already a script directory.

## Acceptance criteria

- [ ] render assertions in `tests/claude-code.bats`: the script downloads to a file, checks it, runs it as `bash <file>`, guards on PATH and on the link, and renders identically for a managed and an unmanaged Mac
- [ ] an installed CLI, whether on PATH or only as `~/.local/bin/claude`, prints nothing and calls neither stub
- [ ] a missing CLI: the script runs the file it downloaded through the bash seam, the temp file is gone afterwards, and the run exits 0
- [ ] an empty download, a failed download and a body that is not a shell script each print the one-line message, never call bash, and exit 0
- [ ] an installer that fails, and one that exits 0 leaving no `~/.local/bin/claude`, each print the one-line message and exit 0
- [ ] `tests/scripts.bats` passes with the new name in the fixed list and in the order test
- [ ] `tests/shellcheck-scripts.sh` clean; nothing in the suite reaches the network or installs the CLI
